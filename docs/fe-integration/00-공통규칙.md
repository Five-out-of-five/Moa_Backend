# 00. 공통 규칙 (BE-1)

> 담당 BE: 이하연(BE-1) · 대상 FE: 주은, 홍근
> 모든 BE API에 공통으로 적용된다. 도메인별 가이드를 보기 전에 먼저 읽어 주세요.

## 1. 주소

| 환경 | 브라우저에서 | FE 서버(BFF)에서 |
|---|---|---|
| 로컬 | `http://localhost:8080` | `http://localhost:8080` |
| 운영 | `https://moayo.site` (CloudFront가 경로로 나눔) | `http://app:8080` (같은 Docker 네트워크) |

운영 CloudFront 경로 나눔
- `/api/v1/*`, `/oauth2/*`, `/login/oauth2/*`, `/ws*`, `/swagger-ui*`, `/v3/api-docs*` → 백엔드(8080)
- 그 밖의 모든 경로 → 프론트(3000)
- 따라서 프론트 BFF 경로는 `/api/v1/` 로 시작하면 안 된다 (예: `/api/rooms/...` 는 OK).
- `/login` 은 프론트 화면이다. 백엔드로 가는 것은 `/login/oauth2/*` 뿐이다.

Swagger: `https://moayo.site/swagger-ui/index.html` (로컬 `http://localhost:8080/swagger-ui/index.html`)

## 2. 인증

- **REST API 는 `Authorization: Bearer {accessToken}` 헤더만 인정한다.**
  - accessToken 쿠키는 REST에서 읽지 않는다. (쿠키 인증은 `/ws` 핸드셰이크 전용, BE-3 담당)
- 인증 없이 부를 수 있는 것: `/api/v1/auth/**`, `/oauth2/**`, `/login/**`
- 그 밖은 모두 로그인 필요. `/api/v1/admin/**` 은 `role=ADMIN` 만.
- 토큰이 없거나 틀림 → `401 COMMON_UNAUTHORIZED`
- 만료 → `401 AUTH_ACCESS_TOKEN_EXPIRED` → `POST /api/v1/auth/refresh` 로 재발급 후 원래 요청을 다시 보낸다. (자세한 내용은 01 문서)
- 권한 부족 → `403 COMMON_FORBIDDEN` (관리자 API를 일반 사용자가 부른 경우 등)

## 3. 성공 응답

HTTP 상태는 **모두 200** 이다 (생성도 201이 아니라 200).

```json
{ "success": true, "data": { ... } }
```

본문이 없는 API(삭제, 로그아웃 등)는 `data` 가 `null` 이다.

```json
{ "success": true, "data": null }
```

### 페이지 응답 (`data` 가 아래 모양)

```json
{
  "content": [ ... ],
  "page": 0,
  "size": 20,
  "totalElements": 57,
  "totalPages": 3,
  "first": true,
  "last": false,
  "hasNext": true
}
```

- 요청: `?page=0&size=20` (page 는 **0부터**, size 기본 20, **최대 100**)
- 목록 중 일부는 페이지가 아니라 배열이다. 각 API 표에 `PageResponse` / `배열` 로 적어 두었다.

## 4. 에러 응답

```json
{
  "success": false,
  "error": {
    "code": "ROOM_NOT_FOUND",
    "message": "방을 찾을 수 없습니다.",
    "traceId": "a1b2c3...",
    "errors": [ { "field": "name", "reason": "2자 이상 30자 이하로 입력해 주세요." } ]
  }
}
```

- **분기는 `error.code` 로 한다.** `message` 는 바뀔 수 있다(그대로 사용자에게 보여 줘도 되는 문장).
- `errors` 는 입력 검증 실패(`400 COMMON_INVALID_INPUT`)일 때만 채워진다. 필드 옆에 표시하면 된다.
- `data` 는 추가 정보가 있을 때만 (예: 정지 해제 시각).
- `errors`, `data` 는 값이 없으면 **키 자체가 빠진다**(`null` 로 오지 않음). `error.data ?? null` 처럼 읽어 주세요.
- `traceId` 는 버그 제보할 때 같이 주세요. 서버 로그를 바로 찾을 수 있다.

### 공통 에러 코드

| 코드 | HTTP | 언제 |
|---|---|---|
| `COMMON_INVALID_INPUT` | 400 | 필수값 누락, 길이·형식 위반, enum 오타, JSON 깨짐 |
| `COMMON_UNAUTHORIZED` | 401 | 토큰 없음/위조 |
| `AUTH_ACCESS_TOKEN_EXPIRED` | 401 | 토큰 만료 → refresh |
| `COMMON_FORBIDDEN` | 403 | 권한 없음 |
| `COMMON_NOT_FOUND` | 404 | 없는 경로 |
| `COMMON_METHOD_NOT_ALLOWED` | 405 | 메서드 틀림 |
| `COMMON_FILE_UPLOAD_FAILED` | 500 | 스토리지 업로드 실패 |
| `COMMON_INTERNAL_ERROR` | 500 | 그 밖의 서버 오류 |

### 예외: CORS 거부는 JSON 이 아니다
허용되지 않은 Origin 에서 브라우저로 부르면 `403` 이고 본문이 **평문 텍스트**(`Invalid CORS request`)다.
JSON 파싱 에러가 나면 Origin 설정부터 확인해 주세요. 허용 Origin 은 운영 `https://moayo.site`, 로컬 `http://localhost:3000`.

## 5. 시간

- **응답의 모든 시각은 한국 시간(KST) ISO-8601**, 오프셋 포함: `"2026-11-22T14:30:00+09:00"`
  - `new Date(value)` 로 그대로 파싱하면 된다.
- **요청으로 보내는 시각도 오프셋을 꼭 붙인다**: `"2026-11-25T09:00:00+09:00"` 또는 `"2026-11-25T00:00:00Z"`
  - 오프셋 없는 `"2026-11-25T09:00:00"` 은 400.
- 날짜만 있는 값(관리자 기간 필터 등)은 한국 날짜 `yyyy-MM-dd`.

## 6. 사람 표시 (MemberRef)

방 안에서 다른 사람을 가리키는 필드(업로더, 작성자 등)는 이 모양이다.

```json
{ "accountId": 12, "displayName": "하연", "profileImageUrl": "https://...", "memberStatus": "ACTIVE" }
```

| memberStatus | displayName / profileImageUrl | FE 표시 예 |
|---|---|---|
| `ACTIVE` | 방 닉네임(없으면 계정 이름) / 방 프로필 이미지 | 그대로 |
| `KICKED` | 값 있음 | 이름 옆 "(내보냄)" 등 |
| `LEFT` | **null** | "나간 멤버" |
| `WITHDRAWN` | **null** | "탈퇴한 사용자" |

## 7. 이미지·파일 URL

- 프로필·방 이미지(`imageUrl`, `profileImageUrl`)는 **바로 `<img src>` 에 넣을 수 있는 공개 URL**이다 (CDN).
- 업로드 직후 받는 `previewUrl` 은 미리보기용 **임시 서명 URL**이다. 화면에 잠깐 보여 주는 용도로만 쓰고 저장하지 않는다.
- 첨부파일은 비공개다. `GET /api/v1/rooms/{roomId}/files/{fileId}/download-url` 로 **서명 URL**을 받아 쓴다. 만료 시각(`expiresAt`)이 있으니 저장해 두지 말고 누를 때마다 받는다. (04 문서)
