# 01. 랜딩·로그인·최초 가입 (BE-1)

> 담당 BE: 이하연 · 대상 FE: 주은
> FE 파일: `features/auth/server.ts`, `features/auth/actions.ts`, `/login`, `/signup`, `/auth/callback`, `ProfileMenu.tsx`
> 공통 규칙(응답 모양, 에러, 시간)은 `00-공통규칙.md` 참고.

## API 목록

| # | 메서드 | 경로 | 인증 | 설명 |
|---|---|---|---|---|
| 1 | GET (브라우저 이동) | `/oauth2/authorization/{provider}` | 없음 | 소셜 로그인 시작 |
| 2 | GET (BE→FE 리다이렉트) | `/login/oauth2/code/{provider}` | 없음 | 소셜 콜백. **FE가 직접 부르지 않음** |

## 전체 흐름

```
[로그인 버튼]
  └─ location.href = "/oauth2/authorization/kakao?returnPath=/rooms/3"
        │ (구글/카카오/네이버 로그인)
        ▼
  BE 콜백 /login/oauth2/code/kakao  ──302──▶  FE 로 돌려보냄 (아래 3가지 중 하나)

  ① 기존 회원      → {FRONTEND_URL}/auth/callback[?returnPath=...]   + refresh 쿠키 심어짐
  ② 신규 회원      → {FRONTEND_URL}/signup?ticket={ticket}[&returnPath=...]
  ③ 로그인 불가    → {FRONTEND_URL}/login?error={코드}[&until=...]
```

`FRONTEND_URL` = 운영 `https://moayo.site`, 로컬 `http://localhost:3000`

### ① 기존 회원: `/auth/callback` 페이지
1. `/auth/callback` 은 **페이지(화면)** 로 만든다. (Route Handler `/api/auth/callback` 이 아님)
2. 페이지가 뜬 뒤 클라이언트에서 `POST /api/v1/auth/refresh` 를 호출해 accessToken 을 받는다. (BFF를 거쳐도 됨)
3. 받은 토큰으로 `GET /api/v1/accounts/me` → `returnPath` 가 있으면 그쪽, 없으면 `lastRoomId` 방 또는 방 목록으로 이동.

> **왜 페이지여야 하나?** refresh 쿠키가 `SameSite=Strict` 라서, 다른 사이트(카카오 등)에서 넘어온 **첫 요청에는 쿠키가 실리지 않는다**.
> 리다이렉트 직후 서버가 바로 refresh 를 부르면 쿠키가 없어 401이 난다. 페이지를 한 번 띄운 뒤 같은 사이트 안에서 부르면 쿠키가 실린다.

### ② 신규 회원: `/signup?ticket=...` 페이지
1. 경로는 **`/signup?ticket=`** (쿼리). `/signup/[ticket]` 동적 경로가 아니다.
2. `GET /api/v1/auth/signup-tickets/{ticket}` 으로 이메일·이름을 받아 폼에 채운다.
3. 약관 동의 + 이름 입력 → `POST /api/v1/auth/signup` → accessToken + refresh 쿠키 → 로그인 완료.
4. 티켓은 **10분** 유효. 지나면 `AUTH_SIGNUP_TICKET_INVALID` → 로그인 화면으로 보내 다시 시작.

### ③ 로그인 실패: `/login?error=...`

| error 값 | 뜻 | 화면 문구 예 |
|---|---|---|
| `AUTH_ACCOUNT_SUSPENDED` | 정지된 계정. `until` 에 해제 시각(KST, 예: `2026-11-25T12:00:00+09:00`, URL 인코딩됨). 영구 정지는 `until` 없음 | "○월 ○일까지 이용이 제한된 계정입니다" |
| `AUTH_REJOIN_RESTRICTED` | 탈퇴한 소셜 계정으로 다시 로그인 | "탈퇴한 계정입니다" |
| `AUTH_EMAIL_ALREADY_REGISTERED` | 같은 이메일이 다른 소셜로 이미 가입됨 | "다른 소셜 계정으로 가입된 이메일입니다" |
| `AUTH_EMAIL_NOT_PROVIDED` | 소셜에서 이메일 제공 동의를 안 함 | "이메일 제공에 동의해 주세요" |
| `AUTH_PROVIDER_NOT_SUPPORTED` | 지원하지 않는 provider, 또는 사용자가 소셜 화면에서 취소 | "로그인에 실패했습니다" |

> 정지 해제 시각은 리다이렉트의 `until` 과 API 에러의 `error.data` 모두 **같은 형식(KST, `+09:00`)** 이다. `new Date(until)` 로 바로 읽으면 된다. 영구 정지는 `until` 이 없고 `error.data` 키도 없다.

## 1. 소셜 로그인 시작

```
GET /oauth2/authorization/{provider}?returnPath={내부경로}
```

- `provider`: `google` | `kakao` | `naver` (소문자)
- `fetch` 가 아니라 **브라우저 이동**(`location.href` 또는 `<a href>`)으로 연다.
- `returnPath`(선택): 로그인 후 돌아갈 FE 경로. `/` 로 시작하는 내부 경로만 받는다 (`//`, `http://...` 는 무시). 5분간 유지되며, 콜백 리다이렉트 주소 뒤에 `returnPath=` 로 그대로 붙여 준다.
  - 예: 초대 링크(`/invite/{code}`)에서 로그인하러 갈 때 `returnPath=/invite/{code}`.

## 3. 가입 티켓 조회

```
GET /api/v1/auth/signup-tickets/{ticket}
```

응답 `data`
```json
{ "provider": "KAKAO", "email": "user@kakao.com", "name": "이하연" }
```
- `name` 은 소셜에서 받은 이름(없으면 빈 문자열). 가입 폼 기본값으로 쓴다.

| 에러 | HTTP | 처리 |
|---|---|---|
| `AUTH_SIGNUP_TICKET_INVALID` | 400 | 만료·없는 티켓 → 로그인 화면으로 |

## 4. 최초 가입

```
POST /api/v1/auth/signup
Content-Type: application/json
```

```json
{ "ticket": "a1b2-...", "name": "이하연", "termsAgreed": true, "privacyAgreed": true }
```

| 필드 | 규칙 |
|---|---|
| `ticket` | 필수 |
| `name` | 필수, 2~20자, 한글·영문·숫자·공백만 (특수문자 불가) |
| `termsAgreed`, `privacyAgreed` | 필수, 둘 다 `true` 여야 함 |

응답 `data` + **Set-Cookie: refreshToken**
```json
{ "accessToken": "eyJ...", "accessTokenExpiresAt": "2026-11-22T16:30:00+09:00" }
```

| 에러 | HTTP | 처리 |
|---|---|---|
| `COMMON_INVALID_INPUT` | 400 | 이름 형식 → `errors[].field == "name"` 표시 |
| `AUTH_TERMS_NOT_AGREED` | 400 | 필수 약관 미동의 |
| `AUTH_SIGNUP_TICKET_INVALID` | 400 | 티켓 만료 → 로그인부터 다시 |
| `AUTH_EMAIL_ALREADY_REGISTERED` | 409 | 이미 가입된 이메일 |

> 가입이 끝나면 티켓은 지워진다. 같은 티켓으로 두 번 가입할 수 없다.

## 5. 토큰 재발급

```
POST /api/v1/auth/refresh
(본문 없음, refreshToken 쿠키가 자동으로 실려야 함)
```

응답 `data` + **새 refreshToken 쿠키** (매번 교체됨)
```json
{ "accessToken": "eyJ...", "accessTokenExpiresAt": "2026-11-22T16:30:00+09:00" }
```

| 에러 | HTTP | 처리 |
|---|---|---|
| `AUTH_REFRESH_TOKEN_INVALID` | 401 | 쿠키 없음·만료·위조 → 로그인 화면으로 |
| `AUTH_ACCOUNT_SUSPENDED` | 403 | 그사이 정지됨. `error.data` 에 해제 시각(KST ISO, 영구면 키 없음) |
| `COMMON_FORBIDDEN` | 403 | Origin 이 허용 목록에 없음 |

- **언제 부르나**: 아무 API 에서 `401 AUTH_ACCESS_TOKEN_EXPIRED` 를 받았을 때, 그리고 페이지 새로고침/첫 진입 때(메모리에 토큰이 없을 때).
- **동시 호출**: 여러 요청이 동시에 만료돼 refresh 가 겹쳐도 서버가 **10초 유예**와 락으로 처리한다. 그래도 FE 에서 refresh 를 한 번만 돌리고 나머지는 기다리게(single-flight) 하는 것을 권장.
- refresh 쿠키가 교체되므로, **BFF 에서 부를 때는 응답의 `Set-Cookie` 를 브라우저에 그대로 넘겨야 한다.** 안 넘기면 다음 refresh 에서 401.

## 6. 로그아웃

```
POST /api/v1/auth/logout
```
- 응답 `data: null`, refresh 쿠키 삭제(`Max-Age=0`). 쿠키가 없어도 성공으로 응답한다.
- FE 는 메모리의 accessToken 도 지운다.

## 토큰·쿠키 정리

| 항목 | 값 |
|---|---|
| accessToken | 응답 본문으로 받음. **FE 가 보관**(메모리 권장) 후 `Authorization: Bearer` 로 보냄. 유효 **2시간** (`accessTokenExpiresAt` 기준) |
| refreshToken | **HttpOnly 쿠키**, JS 에서 읽을 수 없음. 유효 7일, 재발급마다 교체 |
| 쿠키 속성 | `Path=/`, `SameSite=Strict`, `HttpOnly`, 운영 `Secure`, Domain 없음(호스트 전용) |

### Origin 검사 (refresh·logout)
- 요청에 `Origin` 헤더가 **있으면** 허용 목록(`https://moayo.site`, 로컬 `http://localhost:3000`)에 있어야 한다. 아니면 403.
- `Origin` 이 **없으면** 통과 (서버 간 호출, BFF).
- BFF 에서 백엔드로 넘길 때 브라우저 Origin 을 다른 값으로 바꿔 넣지 말 것.

### 로컬 개발 주의
- 로컬은 http 이므로 `COOKIE_SECURE=false` 여야 쿠키가 실린다 (백엔드 로컬 프로필 기본값).
- 프론트 `localhost:3000` → 백엔드 `localhost:8080` 직접 호출 시 `credentials: "include"` 필요. 포트만 다른 같은 사이트라 Strict 쿠키도 실린다.
- 로컬 소셜 콜백 주소는 `http://localhost:8080/login/oauth2/code/{provider}` (각 콘솔에 등록되어 있어야 함).

## 자주 막히는 곳

| 증상 | 원인 |
|---|---|
| 로그인 후 404 | FE 에 `/auth/callback` 또는 `/signup` 페이지가 없음 |
| `/auth/callback` 에서 refresh 가 401 | 리다이렉트 직후 **서버에서** refresh 호출 → Strict 쿠키 안 실림. 페이지 렌더 후 클라이언트에서 호출 |
| 두 번째 refresh 부터 401 | BFF 가 새 `Set-Cookie` 를 브라우저에 안 넘김 |
| 모든 API 가 401 | `Authorization: Bearer` 헤더 누락 (accessToken 쿠키만으로는 인증 안 됨) |
| 로그인 중 갑자기 모든 API 가 403 `AUTH_ACCOUNT_SUSPENDED` | 관리자가 정지함. refresh 토큰도 즉시 지워진다 → 안내 후 로그인 화면으로 |
| refresh 가 403 | 허용되지 않은 Origin |
