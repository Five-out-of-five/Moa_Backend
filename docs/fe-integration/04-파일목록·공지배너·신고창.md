## 파일

### 업로드 규칙

| purpose | 쓰는 곳 | 허용 확장자 | 최대 크기 |
|---|---|---|---|
| `PROFILE_IMAGE` | 방별 프로필 사진 (02 문서) | jpg, jpeg, png, webp | 5MB |
| `ROOM_IMAGE` | 방 이미지 (03 문서), **방장만** | jpg, jpeg, png, webp | 5MB |
| `CHAT_ATTACHMENT` | 채팅 첨부 | jpg, jpeg, png, gif, webp, pdf, docx, xlsx, pptx, txt, md, zip | 20MB |
| `CARD_ATTACHMENT` | 아이디어 카드 첨부 | 위와 같음 | 20MB |
| `TASK_ATTACHMENT` | 할 일 첨부 | 위와 같음 | 20MB |

- 방 전체 용량 **2GB**. 넘으면 `FILE_STORAGE_LIMIT_EXCEEDED`.
- 카드·할 일·채팅 하나에 첨부는 **최대 5개** (각 도메인 API 에서 검사, `FILE_ATTACHMENT_LIMIT_EXCEEDED`).

### 업로드 → 연결 흐름 (모든 첨부 공통)
```
1. POST /files?purpose=CARD_ATTACHMENT  → fileId
2. 카드/할 일/메시지/프로필/방 저장 API 에 fileId (또는 fileIds) 를 넣어 보냄  → 이때 "연결"됨
3. 저장 전에 취소하면 DELETE /files/{fileId}
```
- 연결되지 않은 파일은 파일 목록(3번)에 나오지 않는다.
- 이미 연결된 파일을 다른 곳에 또 넣으면 `FILE_ALREADY_ATTACHED`.

### 1. 파일 업로드 — multipart

```
POST /api/v1/rooms/{roomId}/files?purpose=CHAT_ATTACHMENT
Content-Type: multipart/form-data
part "file" = 파일
```
```ts
const form = new FormData();
form.append("file", file);
await fetch(`${API}/api/v1/rooms/${roomId}/files?purpose=CHAT_ATTACHMENT`, {
  method: "POST", headers: { Authorization: `Bearer ${token}` }, body: form,
});
```
- `purpose` 는 **쿼리 파라미터**다 (form part 아님).

응답 `data`: FileResponse
```json
{
  "fileId": 41,
  "originalName": "회의록.pdf",
  "mimeType": "application/pdf",
  "sizeBytes": 183021,
  "purpose": "CHAT_ATTACHMENT",
  "previewUrl": null
}
```
- `previewUrl`: 이미지(jpg/jpeg/png/gif/webp)일 때만 있음. **1시간짜리 임시 서명 URL** → 업로드 직후 미리보기에만 사용.

| 에러 | HTTP | 처리 |
|---|---|---|
| `FILE_TYPE_NOT_ALLOWED` | 400 | 허용 안 되는 확장자 |
| `FILE_SIZE_EXCEEDED` | 413 | 크기 초과 |
| `FILE_STORAGE_LIMIT_EXCEEDED` | 409 | 방 용량 2GB 초과 |
| `ROOM_OWNER_ONLY` | 403 | ROOM_IMAGE 를 방장이 아닌 사람이 올림 |
| `COMMON_INVALID_INPUT` | 400 | `purpose` 누락/오타, `file` part 누락 |
| `COMMON_FILE_UPLOAD_FAILED` | 500 | 스토리지 오류 → 다시 시도 |

> 413 은 업로드 크기 제한에 걸린 것이다. 서버의 요청 크기 한도는 25MB 라서, 그보다 큰 파일은 서버 앞단에서 바로 끊길 수 있다. **보내기 전에 FE 에서 크기·확장자를 먼저 검사**해 주세요.

### 2. 업로드 취소

```
DELETE /api/v1/rooms/{roomId}/files/{fileId}
```
- 아직 **어디에도 연결되지 않은** 내 파일만 지울 수 있다. 응답 `data: null`.

| 에러 | HTTP | 처리 |
|---|---|---|
| `FILE_NOT_FOUND` | 404 | 없거나 다른 방 파일 |
| `FILE_NOT_OWNER` | 403 | 남이 올린 파일 |
| `FILE_ALREADY_ATTACHED` | 409 | 이미 카드 등에 연결됨 (첨부 삭제는 해당 도메인 API 로) |

### 3. 방 파일 목록 — Page (`RoomFileTable.tsx`)

```
GET /api/v1/rooms/{roomId}/files?source=IDEA_CARD&fileType=DOCUMENT&uploaderId=12&keyword=회의&page=0&size=20
```

| 파라미터 | 값 | 설명 |
|---|---|---|
| `source` | `CHAT` \| `IDEA_CARD` \| `TASK` | 어디에 첨부된 파일인지 |
| `fileType` | `IMAGE` \| `DOCUMENT` \| `ARCHIVE` | IMAGE=`image/*`, DOCUMENT=`application/*`(pdf·docx 등, zip 포함), ARCHIVE=zip |
| `uploaderId` | 계정 ID | 올린 사람 |
| `keyword` | 문자열 | 파일 이름 부분 검색(대소문자 무시) |
| `page`, `size` | | 기본 0, 20 |

모두 선택. 최신 업로드 순.

```json
{
  "content": [
    {
      "fileId": 41,
      "originalName": "회의록.pdf",
      "mimeType": "application/pdf",
      "sizeBytes": 183021,
      "uploader": { "accountId": 12, "displayName": "하연", "profileImageUrl": null, "memberStatus": "ACTIVE" },
      "source": "IDEA_CARD",
      "sourceId": 77,
      "uploadedAt": "2026-11-22T10:00:00+09:00"
    }
  ],
  "page": 0, "size": 20, "totalElements": 1, "totalPages": 1, "first": true, "last": true, "hasNext": false
}
```
- `sourceId`: 카드 ID / 할 일 ID / 메시지 ID. "원본으로 이동" 링크에 사용.
- 프로필·방 이미지는 목록에 나오지 않는다. 지워진 카드·할 일·메시지의 첨부도 안 나온다.
- 업로더가 나갔거나 탈퇴하면 `uploader.displayName` 이 `null` (00 문서 MemberRef).
- `source`, `fileType` 에 정의되지 않은 값을 넣으면 필터가 무시된다(전체 조회).

### 4. 다운로드 URL

```
GET /api/v1/rooms/{roomId}/files/{fileId}/download-url
```
```json
{ "url": "https://moa-bucket-....s3.ap-northeast-2.amazonaws.com/rooms/3/...?X-Amz-...", "expiresAt": "2026-11-22T10:10:00+09:00" }
```
- **10분** 유효한 서명 URL. 받는 즉시 `location.href = url` 또는 `<a href={url}>` 로 연다. 원래 파일 이름으로 내려받아진다.
- 저장해 두었다 쓰지 말고 **누를 때마다** 새로 받는다.
- BFF 다운로드 중계(`app/api/rooms/[roomId]/files/[fileId]/download/route.ts`)는: 이 API 를 Bearer 로 호출 → 받은 `url` 로 **302 리다이렉트**만 하면 된다. 파일 내용을 BFF 가 다시 받아 넘길 필요 없다.

| 에러 | HTTP | 처리 |
|---|---|---|
| `FILE_NOT_FOUND` | 404 | 없거나 다른 방 파일 |

### 5. 방 저장 용량

```
GET /api/v1/rooms/{roomId}/storage-usage
```
```json
{ "usedBytes": 524288000, "limitBytes": 2147483648 }
```
- 파일 목록 상단의 "500MB / 2GB" 표시용.

## 공지

### 공지 종류

| noticeType | 표시 |
|---|---|
| `URGENT` | 화면 상단 **배너** (`banner` 로 따로 내려옴) |
| `MAINTENANCE` | 점검 공지. `maintenanceStartsAt`(점검 시작 시각) 있음 |
| `GENERAL` | 일반 공지 |

### 6. 지금 띄울 공지 (`NoticeBanner.tsx`)

```
GET /api/v1/notices/active
```
```json
{
  "banner": { "noticeId": 9, "noticeType": "URGENT", "title": "긴급 점검 안내" },
  "notices": [
    { "noticeId": 9, "noticeType": "URGENT", "title": "긴급 점검 안내", "displayEndsAt": "2026-11-23T00:00:00+09:00" },
    { "noticeId": 7, "noticeType": "GENERAL", "title": "새 기능 안내", "displayEndsAt": "2026-11-30T00:00:00+09:00" }
  ]
}
```
- **지금 게시 기간 안**이고 **내가 닫지 않은** 공지만 내려온다.
- `banner`: 그중 URGENT 1개. 없으면 `null`. (`notices` 에도 포함되어 있음)
- 예외: `MAINTENANCE` 공지는 **점검이 시작되기 전까지는 닫아도 계속 내려온다**(놓치지 않게).
- 앱 진입 시, 방 이동 시 등 적당한 시점에 호출. 실시간 푸시는 없다.

### 7. 공지 목록 — Page

```
GET /api/v1/notices?page=0&size=20
```
```json
{ "content": [ { "noticeId": 7, "noticeType": "GENERAL", "title": "새 기능 안내", "displayStartsAt": "2026-11-20T00:00:00+09:00" } ], "page": 0, ... }
```
- 게시 시작일 최신순. 닫은 공지도 여기선 보인다.

### 8. 공지 상세

```
GET /api/v1/notices/{noticeId}
```
```json
{
  "noticeId": 7,
  "noticeType": "MAINTENANCE",
  "title": "정기 점검 안내",
  "content": "## 점검 내용\n- 서버 교체\n...",
  "displayStartsAt": "2026-11-20T00:00:00+09:00",
  "displayEndsAt": "2026-11-30T00:00:00+09:00",
  "maintenanceStartsAt": "2026-11-25T02:00:00+09:00"
}
```
- `content` 는 **Markdown**. 렌더링 시 HTML 은 sanitize 해 주세요.
- `maintenanceStartsAt` 은 MAINTENANCE 일 때만 값이 있다.

| 에러 | HTTP | 처리 |
|---|---|---|
| `NOTICE_NOT_FOUND` | 404 | 없거나 삭제된 공지 |

### 9. 공지 닫기

```
POST /api/v1/notices/{noticeId}/dismiss
```
- 응답 `data: null`. 이후 6번에서 빠진다(MAINTENANCE 는 위 예외). 계정 기준이라 다른 기기에서도 안 보인다.
- 여러 번 불러도 괜찮다.

| 에러 | HTTP | 처리 |
|---|---|---|
| `NOTICE_NOT_FOUND` | 404 | 없거나 삭제된 공지 |

## 신고 (`ReportMenu.tsx`)

### 10. 신고하기

```
POST /api/v1/reports
{ "targetType": "MESSAGE", "targetId": 1234, "reason": "ABUSE", "detail": "욕설이 포함되어 있습니다." }
```

| 필드 | 규칙 |
|---|---|
| `targetType` | 필수. `CARD`(아이디어 카드) \| `COMMENT`(카드 댓글) \| `MESSAGE`(채팅 메시지) |
| `targetId` | 필수. 카드 ID / 댓글 ID / 메시지 ID |
| `reason` | 필수. `ABUSE`(욕설·비방) \| `SPAM`(스팸·광고) \| `INAPPROPRIATE_FILE`(부적절한 파일) \| `PRIVACY`(개인정보 노출) \| `ETC`(기타) |
| `detail` | 선택, 최대 500자 |

응답 `data`
```json
{ "reportId": 31, "status": "RECEIVED", "createdAt": "2026-11-22T10:00:00+09:00" }
```
- 신고자에게 알림 `REPORT_RECEIVED`. 처리되면 관리자 쪽에서 결과 알림이 간다.
- 신고 시점의 내용이 저장되므로, 작성자가 나중에 글을 지워도 관리자는 볼 수 있다.
- **내 글에는 신고 메뉴를 숨겨** 주세요(보내면 400).

| 에러 | HTTP | 처리 |
|---|---|---|
| `REPORT_OWN_CONTENT` | 400 | 내가 쓴 글 |
| `REPORT_DUPLICATED` | 409 | 같은 대상을 이미 신고함 → "이미 신고한 내용입니다" |
| `REPORT_BLOCKED` | 403 | 허위 신고로 신고 기능이 일시 제한됨 |
| `REPORT_TARGET_NOT_FOUND` | 404 | 대상이 없거나 이미 삭제됨 |
| `ROOM_NOT_MEMBER` | 403 | 대상이 있는 방의 멤버가 아님 |
| `COMMON_INVALID_INPUT` | 400 | enum 오타, detail 500자 초과 |
