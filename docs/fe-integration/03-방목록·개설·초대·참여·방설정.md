# 03. 방 목록·개설·초대·참여·방 설정 (BE-1)

> 담당 BE: 이하연 · 대상 FE: 주은

## 방 공통 에러

방 안의 API(3~17, 파일·보드 등 다른 도메인 포함)에서 공통으로 나올 수 있다.

| 코드 | HTTP | 뜻 / FE 처리 |
|---|---|---|
| `ROOM_NOT_FOUND` | 404 | 없거나 삭제된 방 → 방 목록으로 |
| `ROOM_NOT_MEMBER` | 403 | 내가 멤버가 아님(나감·내보내짐 포함) → 방 목록으로 |
| `ROOM_OWNER_ONLY` | 403 | 방장 전용 기능 |
| `ROOM_INACTIVE` | 403 | 관리자가 비활성화한 방. 들어갈 수 없음 → "운영 정책에 따라 비활성화된 방입니다" |

## 제한값

| 항목 | 값 |
|---|---|
| 방 이름 | 2~30자 |
| 방 설명 | 최대 200자 |
| 방 최대 인원 | 20명 (방장 포함) |
| 내가 만들 수 있는 방 | 10개 (삭제한 방은 제외하고 셈) |
| 참여 요청 유효기간 | 7일 (지나면 `EXPIRED`) |
| 방 이미지 | jpg/png/webp, 5MB |

## 방

### 공통 응답: RoomDetailResponse (1·3·4번)

```json
{
  "roomId": 3,
  "name": "캡스톤 5조",
  "description": "모아 프로젝트 방",
  "imageUrl": "https://d3fhahas6mrxzx.cloudfront.net/public/...",
  "status": "ACTIVE",
  "memberCount": 4,
  "maxMemberCount": 20,
  "myMembership": {
    "role": "OWNER",
    "nickname": "하연",
    "displayName": "하연",
    "profileImageUrl": null,
    "positionLabel": "백엔드",
    "notificationMuted": false,
    "joinedAt": "2026-11-01T10:00:00+09:00"
  },
  "needsProfileSetup": false
}
```
- `imageUrl`: 없으면 `null` → 기본 이미지.
- `myMembership.nickname`: 방 닉네임 원본(없으면 `null`). 화면 표시용은 `displayName`(닉네임 없으면 계정 이름).
- `needsProfileSetup: true` → 최초 프로필 폼(`FirstProfileForm.tsx`) 표시. 방을 만든 방장은 처음부터 `false`.

### 1. 방 개설 — multipart

```
POST /api/v1/rooms
Content-Type: multipart/form-data
```

| part 이름 | 타입 | 내용 |
|---|---|---|
| `request` | **application/json** | `{ "name": "캡스톤 5조", "description": "..." }` |
| `image` | 파일 (선택) | 방 이미지 |

```ts
const form = new FormData();
form.append("request", new Blob([JSON.stringify({ name, description })], { type: "application/json" }));
if (imageFile) form.append("image", imageFile);
await fetch(`${API}/api/v1/rooms`, { method: "POST", headers: { Authorization: `Bearer ${token}` }, body: form });
// Content-Type 은 직접 넣지 말 것 (boundary 를 브라우저가 붙인다)
```
- `request` part 를 그냥 문자열로 append 하면 Content-Type 이 없어 **400/415** 가 난다. 반드시 `Blob(..., {type:"application/json"})`.
- 응답: RoomDetailResponse. 만든 사람은 방장이 된다.

| 에러 | HTTP | 처리 |
|---|---|---|
| `COMMON_INVALID_INPUT` | 400 | 이름·설명 길이 → `errors[].field` |
| `ROOM_CREATE_LIMIT_EXCEEDED` | 409 | "방은 최대 10개까지 만들 수 있습니다" |
| `FILE_TYPE_NOT_ALLOWED` | 400 | 이미지 형식 |
| `FILE_SIZE_EXCEEDED` | 413 | 5MB 초과 |

### 2. 내 방 목록 — 배열

```
GET /api/v1/rooms
```
```json
[
  { "roomId": 3, "name": "캡스톤 5조", "imageUrl": null, "myRole": "OWNER", "memberCount": 4, "status": "ACTIVE" }
]
```
- 내가 **활동 중(ACTIVE)** 인 방만. 페이지 아님.
- `status: INACTIVE` 인 방도 목록에는 나온다 → 회색 처리하고 들어가기 막기(들어가면 `ROOM_INACTIVE`).
- `/workspaces` 화면, `WorkspaceSwitcher.tsx` 에서 사용.

### 3. 방 상세

```
GET /api/v1/rooms/{roomId}
```
방에 들어갈 때 호출. 이어서 `PUT /api/v1/accounts/me/last-room` 도 불러 주세요(02 문서).

### 4. 방 설정 변경 (방장)

```
PATCH /api/v1/rooms/{roomId}
{ "name": "새 이름", "description": "새 설명", "imageFileId": 52 }
```
**보낸 키만 바뀐다.**

| 필드 | 키를 안 보냄 | 값을 보냄 | `null` 을 보냄 |
|---|---|---|---|
| `name` | 그대로 | 변경 (2~30자) | 그대로 |
| `description` | 그대로 | 변경 (≤200자) | 그대로 |
| `imageFileId` | **그대로** | 이미지 교체 | **이미지 삭제(기본 이미지)** |

- 이미지 교체 순서: `POST /api/v1/rooms/{roomId}/files?purpose=ROOM_IMAGE` (multipart `file`) → `fileId` → 이 API 에 `imageFileId`. (04 문서)
- `ROOM_IMAGE` 업로드는 방장만 가능.
- 응답: RoomDetailResponse. 같은 방 사람들에게 실시간 `ROOM_UPDATED` 이벤트.

| 에러 | HTTP | 처리 |
|---|---|---|
| `ROOM_OWNER_ONLY` | 403 | 방장 아님 |
| `FILE_NOT_FOUND` / `FILE_NOT_OWNER` / `FILE_PURPOSE_MISMATCH` | 404/403/400 | 잘못된 imageFileId |

### 5. 방 삭제 (방장)

```
DELETE /api/v1/rooms/{roomId}
Content-Type: application/json
{ "confirmName": "캡스톤 5조" }
```
- DELETE 이지만 **본문이 있다**. `confirmName` 은 **현재 방 이름과 정확히 같아야** 한다(사용자가 입력한 값).
- 응답 `data: null`. 방 안에 있던 사람들에게 실시간 `ROOM_DELETED` → 방 목록으로 보내기.

| 에러 | HTTP | 처리 |
|---|---|---|
| `ROOM_DELETE_CONFIRM_MISMATCH` | 400 | "방 이름이 일치하지 않습니다" |

## 초대·참여

### 흐름
```
방장: 6. 초대 링크 받기 → inviteUrl 복사해서 공유 ( https://moayo.site/invite/{inviteCode} )
참여자: /invite/{inviteCode} 화면(InviteEntry.tsx)
   ├─ 로그인 안 됨 → /oauth2/authorization/{provider}?returnPath=/invite/{inviteCode}  (01 문서)
   ├─ 7. 미리보기 → myStatus 에 따라 버튼 분기
   └─ 8. 참여 요청 → PENDING
방장: 알림 JOIN_REQUESTED → 9. 목록 → 10 승인 / 11 거절
참여자: 알림 JOIN_PROCESSED ("승인되었습니다" / "거절되었습니다")
```
- FE 에 **`/invite/[inviteCode]` 페이지**가 있어야 한다 (BE 가 만들어 주는 링크 주소).
- **내가 보낸 참여 요청 목록 API 는 없다.** 결과는 알림 `JOIN_PROCESSED` 로 받는다. 대기 중인지는 7번 미리보기의 `myStatus: PENDING` 으로 확인.

### 6. 초대 링크 (방장)

```
GET /api/v1/rooms/{roomId}/invite-link
```
```json
{ "inviteCode": "3f2a9c...", "inviteUrl": "https://moayo.site/invite/3f2a9c..." }
```
- 방마다 코드는 하나이고 바뀌지 않는다.

### 7. 초대 미리보기

```
GET /api/v1/invites/{inviteCode}
```
```json
{ "roomId": 3, "name": "캡스톤 5조", "description": "...", "imageUrl": null, "memberCount": 4, "myStatus": "NONE" }
```

| myStatus | 뜻 | 버튼 |
|---|---|---|
| `NONE` | 참여 가능 | "참여 요청" |
| `PENDING` | 이미 요청함, 방장 대기 | "승인 대기 중" (비활성) |
| `MEMBER` | 이미 멤버 | "방으로 이동" → `/rooms/{roomId}` |
| `KICKED` | 내보내진 적 있음 | "참여할 수 없습니다" |
| `FULL` | 20명 꽉 참 | "인원이 가득 찼습니다" |

| 에러 | HTTP | 처리 |
|---|---|---|
| `INVITE_CODE_NOT_FOUND` | 404 | 잘못된 링크 / 삭제된 방 |
| `ROOM_INACTIVE` | 403 | 비활성화된 방 |

### 8. 참여 요청

```
POST /api/v1/invites/{inviteCode}/join-requests
(본문 없음)
```
응답: JoinRequestResponse (아래). 방장에게 알림 `JOIN_REQUESTED`.

| 에러 | HTTP | 처리 |
|---|---|---|
| `JOIN_ALREADY_MEMBER` | 409 | 이미 멤버. `error.data.roomId` 로 방 이동 |
| `JOIN_KICKED_MEMBER` | 403 | 내보내진 방 |
| `JOIN_REQUEST_ALREADY_PENDING` | 409 | 이미 대기 중 |
| `ROOM_MEMBER_LIMIT_EXCEEDED` | 409 | 20명 꽉 참 |
| `INVITE_CODE_NOT_FOUND` / `ROOM_INACTIVE` | 404 / 403 | 7번과 같음 |

### JoinRequestResponse (8·9·10·11번)

```json
{
  "requestId": 15,
  "roomId": 3,
  "requester": { "accountId": 20, "name": "김모아" },
  "status": "PENDING",
  "requestedAt": "2026-11-22T10:00:00+09:00",
  "expiresAt": "2026-11-29T10:00:00+09:00",
  "processedAt": null
}
```
- `requester.name` 은 **계정 이름**(아직 방 닉네임이 없으니까).

### 9. 참여 요청 목록 (방장) — Page

```
GET /api/v1/rooms/{roomId}/join-requests?status=PENDING&page=0&size=20
```
- `status`: `PENDING`(기본) | `APPROVED` | `REJECTED` | `EXPIRED`
- 최신 요청 순. `RoomManagementDetails.tsx` 의 요청 관리 탭.

### 10. 승인 / 11. 거절 (방장)

```
POST /api/v1/rooms/{roomId}/join-requests/{requestId}/approve
POST /api/v1/rooms/{roomId}/join-requests/{requestId}/reject
(본문 없음)
```
- 응답: 처리된 JoinRequestResponse (`status`, `processedAt` 채워짐).
- 승인 시: 요청자에게 `JOIN_PROCESSED` 알림, 기존 멤버들에게 `MEMBER_JOINED` 알림, 방에 실시간 `MEMBER_JOINED`.
- 거절 시: 요청자에게 `JOIN_PROCESSED` 알림.
- 예전에 나갔던 사람이 다시 들어오면 새 멤버처럼 `needsProfileSetup: true` 부터 시작.

| 에러 | HTTP | 처리 |
|---|---|---|
| `JOIN_REQUEST_NOT_FOUND` | 404 | 다른 방 요청이거나 없음 |
| `JOIN_REQUEST_ALREADY_PROCESSED` | 409 | 이미 처리/만료됨 → 목록 새로고침 |
| `ROOM_MEMBER_LIMIT_EXCEEDED` | 409 | (승인만) 20명 꽉 참 |

## 멤버

### 12. 멤버 목록 — 배열

```
GET /api/v1/rooms/{roomId}/members
```
```json
[
  {
    "accountId": 12,
    "displayName": "하연",
    "profileImageUrl": null,
    "positionLabel": "백엔드",
    "role": "OWNER",
    "online": true,
    "todayMood": { "mood": "GOOD", "comment": "화이팅" }
  }
]
```
- 활동 중인 멤버만. `todayMood` 는 오늘(KST) 기분을 안 남겼으면 `null`.
- `online` 은 조회 시점 값. 실시간 변화는 STOMP 이벤트로(BE-3 가이드).

### 13. 멤버 프로필

```
GET /api/v1/rooms/{roomId}/members/{accountId}
```
응답: MemberProfileResponse (02 문서 7번과 같은 모양)
- 나간/내보낸/탈퇴한 사람도 조회된다. `memberStatus` 로 구분하고, 이때 `positionLabel` 은 `null`.
- `latestMood`: 가장 최근 기분(오늘이 아닐 수 있음).
- `canStartDirectMessage`: DM 버튼 노출 여부(본인·비활성 멤버면 `false`).

| 에러 | HTTP | 처리 |
|---|---|---|
| `MEMBER_NOT_FOUND` | 404 | 이 방에 있었던 적이 없는 계정 |

### 14. 나가기 가능 여부

```
GET /api/v1/rooms/{roomId}/members/me/leave-check
```
```json
{ "leavable": false, "isOwner": true, "assignedOpenTaskCount": 2 }
```
- `isOwner: true` → 나갈 수 없음. "방장을 위임한 뒤 나갈 수 있습니다" (17번으로 연결)
- `assignedOpenTaskCount > 0` → "완료하지 않은 할 일 N개가 있습니다" 경고 (나가기는 가능)

### 15. 방 나가기

```
DELETE /api/v1/rooms/{roomId}/members/me
```
- 응답 `data: null`. 방에 실시간 `MEMBER_LEFT`. FE 는 방 목록으로 이동.
- 나간 뒤 내 이름은 방 안에서 "나간 멤버"(`memberStatus: LEFT`, 이름·사진 null)로 보인다.
- 초대 링크로 다시 요청할 수 있다.

| 에러 | HTTP | 처리 |
|---|---|---|
| `MEMBER_OWNER_CANNOT_LEAVE` | 409 | 방장은 위임 먼저 |

### 16. 내보내기 (방장)

```
DELETE /api/v1/rooms/{roomId}/members/{accountId}
```
- 응답 `data: null`. 대상에게 알림 `MEMBER_KICKED`, 방에 실시간 `MEMBER_LEFT`, 대상의 소켓 연결은 끊긴다.
- 내보낸 사람은 **다시 참여 요청할 수 없다** (`JOIN_KICKED_MEMBER`).

| 에러 | HTTP | 처리 |
|---|---|---|
| `MEMBER_CANNOT_KICK_SELF` | 400 | 자기 자신 |
| `MEMBER_NOT_FOUND` | 404 | 활동 중인 멤버가 아님 |

### 17. 방장 위임 (방장)

```
POST /api/v1/rooms/{roomId}/delegate-owner
{ "targetAccountId": 20 }
```
- 응답: **바뀐 멤버 목록**(12번과 같은 배열). 나는 `MEMBER`, 대상은 `OWNER`.
- 대상에게 알림 `ROLE_CHANGED`, 방에 실시간 `MEMBER_UPDATED`.
- 위임 후 내 화면의 방장 메뉴를 숨겨야 하니 `GET /api/v1/rooms/{roomId}` 를 다시 부르거나 `myMembership.role` 을 갱신.

| 에러 | HTTP | 처리 |
|---|---|---|
| `MEMBER_DELEGATE_TARGET_INVALID` | 400 | 자기 자신, 또는 나간/내보낸 멤버 |
| `MEMBER_NOT_FOUND` | 404 | 이 방에 있었던 적 없는 계정 |

## 이 화면과 관련된 알림·실시간 이벤트 (참고)

| 종류 | 이름 | 받는 사람 | 언제 |
|---|---|---|---|
| 알림 | `JOIN_REQUESTED` | 방장 | 참여 요청 |
| 알림 | `JOIN_PROCESSED` | 요청자 | 승인/거절 |
| 알림 | `MEMBER_JOINED` | 기존 멤버 | 승인 |
| 알림 | `MEMBER_KICKED` | 내보내진 사람 | 내보내기 |
| 알림 | `ROLE_CHANGED` | 새 방장 | 위임 |
| 실시간 | `ROOM_UPDATED` / `ROOM_DELETED` | 방 | 설정 변경 / 삭제 |
| 실시간 | `MEMBER_JOINED` / `MEMBER_LEFT` / `MEMBER_UPDATED` | 방 | 합류 / 나감·내보냄 / 프로필·역할 변경 |

알림 목록·실시간 구독 방법은 알림/STOMP 담당 BE 가이드를 봐 주세요.
